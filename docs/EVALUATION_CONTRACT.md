# Offline evaluation contract

The same authored action is replayed under baseline and guarded policies:

`proposal → permission gate → virtual state change → independent fixture oracle`

The gate reads trusted authorization and test evidence, never the fixture's `oracle_good` answer. Known outcomes, unknown responses, useful normal actions, false blocks, bad proposals and accepted harmful state changes are separate fields.

The demo does not infer a caller's intent, generate code, perform live speech recognition or execute model-generated programs. Its independent oracle is an authored expected-outcome label, not a complete client integration. For a client engagement, the approved trace adapter and state oracle are scoped to that workflow.

Blocked actions do not mutate the virtual ledger. Missing responses keep null success/error/loss fields and do not become safe outcomes. Monetary impact is a synthetic fixture amount, not an offered price. Financial-pricing calculations are not part of this release.

Research configuration uses seven axes: workflow, stack, authority, controls, recovery, context and horizon. Source cell IDs refer to the original complete configuration; displayed fields are a public projection. Repeated seeds or policies are not independent customer cases.
